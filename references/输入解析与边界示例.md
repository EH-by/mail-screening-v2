# 输入解析与边界示例（Q1 / Q2）

> 本文件是 SKILL.md §5.3（Q1 输入解析规则）与 §5.4（Q2 模式参数解析）的补充工作示例。
> 当解析不确定时查阅本表对照；表中数值均为示意【此为例】。
> 所有"已记录"复述仅为解析回显（同一轮内澄清），不是新问题，不构成第二轮 grilling。

## ⚠️ 使用前提（先读）

1. **不预设表格模板**：本文件中的列名（性别、意向教练性别、一等奖意向奖励等）与表格形态（腾讯问卷导出）**只是已知形态之一，不代表所有情况，更不代表常见格式**。真实表的列名、取值、编码、结构以每次执行的「表头识别 + 可筛列提取」结果为准——列名千差万别（手工表、其他问卷平台、混合格式），但识别逻辑一致。
2. **不预设用户说法**：用户输入可以是格式串（`2b`）、自然语言（"保留女生"）、混输（"选2保留女"）、省略（"女"）、"随便"——**先识别意图再落参数**，任何解析都要回显复述让用户确认或纠正。
3. 本文件示例中的取值（男/女、1/2/3 编码）均为演示，真实取值以表格数据为准。

## 一、已知表格形态示例（之一：腾讯问卷导出）【此为例】

| 列（表头原文示例） | 识别为 | 处理 |
|---|---|---|
| 序号 / 所用时间 / 来源 / 来源详情 / 来自IP | 平台元数据列 | 跳过，摘要注明 |
| 提交答卷时间（`2025/11/10 19:12:12`） | 报名时间 | 归一为 YYYY-MM-DD（保留至秒用于排序） |
| 1、姓名 / 2、性别 / 3、学号 | 姓名 / 性别 / 学号 | 正常使用（表头先剥离 `数字+、` 前缀） |
| 4、微信（微信号或手机号） | 联系方式 | 名单与内部记录保留；**不进收件人串**（收件人串 = 推导的学校邮箱） |
| 5、平时常去的健身房（多选）(上园…)/(下园…) | 多选拆列（0/1 编码） | 摘要注明"第 5 题为多选，拆为 2 列"；不进可筛列 |
| 6、意向教练性别（1/2 编码） / 7、8、意向奖励（1/2/3 编码） | 可筛列（编码） | 进 Q1 可筛列选项，标注"（编码）"，请用户口述取值含义 |

**其他常见形态（不限于）**：手工整理表（列名如"姓名/学号/邮箱/备注"，无元数据列无前缀）；问卷星/金数据等平台导出（列名与腾讯问卷不同，但元数据列与前缀逻辑类似）；合并多个来源的表（列结构不一致，缺失列留空并注明）。

## 二、Q1 格式输入 · 解析正例

| 用户输入 | 解析过程 | 解析结果（回显文案示例） |
|---|---|---|
| `1` | 数字段=1 | 类型1 按报名时间先后（先到先得），无参数 |
| `2b` | 数字段=2，字母段=b（列） | 类型2 选 b 列（意向教练性别）→ 同一轮内追问取值：`b 列取值：a.1[33] b.2[15]（编码，含义？）` |
| `2b a`（追问后） | 取值字母 a | 已记录：类型2 意向教练性别=保留 1（编码，用户口述含义后记入规则原文） |
| `2b !a`（追问后） | 取值带 `!` 前缀 | 已记录：类型2 意向教练性别=剔除 1（保留其余） |
| `3a` | 数字段=3，字母段=a（列） | 类型3 选 a 列（性别）→ 追问取值优先级 |
| `3a b,a`（追问后） | 取值优先级 b→a | 已记录：类型3 性别优先 女→男，其余按默认 |
| `2b+3a` | 归一化=2b3a，按位拆分 | 类型4 组合：类型2（b 列）→ 类型3（a 列），各自随后追问取值 |
| `23` | 按位拆分 | 同 "2+3"：类型2 + 类型3（执行顺序=数字出现顺序） |
| `b` | 纯字母无数字 | 默认类型3：b=列字母，无优先级 → 追问取值优先级；也可按"仅该列优先"缺省处理并注明 |
| `5` | 含 5（自定义） | 追问规则内容一次 → 不回 → 缺省：不筛选并注明 |
| `随便` / `按默认` / 不答 | 命中缺省值表 | Q1 缺省：不筛选（全员进入判定），摘要注明"本次未设置筛选规则" |

## 三、Q1 自然语言输入 · 解析正例（用户说法千差万别，先识别意图再落参数）

| 用户输入 | 意图识别 → 映射 | 解析结果（回显文案示例） |
|---|---|---|
| `保留女生` | "保留" → 类型2；"女生"→ 性别列取值"女" | 已记录：类型2 性别=保留 女 |
| `只要本科生` | "只要" → 类型2；"本科生"→ 身份列取值 | 已记录：类型2 身份=保留 本科生 |
| `把研究生剔掉` | "剔掉" → 类型2（剔除方向）；"研究生"→ 身份列取值 | 已记录：类型2 身份=剔除 研究生（保留其余） |
| `不要教职工` | "不要" → 类型2 剔除 | 已记录：类型2 身份=剔除 教职工 |
| `除了大一的都要` | "除了…都要" → 类型2 剔除；"大一"→ 年级列取值 | 已记录：类型2 年级=剔除 大一（保留其余） |
| `意向教练性别要女的` | "要…的" → 类型2；"意向教练性别"→ 列、"女的"→ 取值（若列是 1/2 编码，先确认 2=女） | 已记录：类型2 意向教练性别=保留 2（女，编码含义已确认） |
| `先考虑研究生` | "先考虑" → 类型3；"研究生"→ 身份列取值 | 已记录：类型3 身份优先 研究生，其余按默认 |
| `报名的按先到先得` | "先到先得" → 类型1 | 已记录：类型1 按报名时间先后（先到先得） |
| `先按意向教练性别筛保留女，再按性别优先` | "先…再…" → 类型4；"筛…保留" → 类型2；"优先" → 类型3 | 已记录：类型4 组合：类型2 意向教练性别=保留 女 → 类型3 性别优先，按句子顺序执行 |
| `选2保留女` | 混输：数字段=2 → 类型2；"保留女" → 参数 | 已记录：类型2 性别=保留 女 |
| `录取30个，候补10个` | 筛选部分为空，判定部分=名额制 | 已记录：筛选规则=未设置；判定规则（Q2）=模式A 录取 30、候补 10——判定部分在 Q2 直接采用 |
| `选5 按一等奖意向奖励分组通知` | 含 5 → 整段为自定义规则原文 | 类型5 自定义："按一等奖意向奖励分组通知"，原样回存 |
| `随便` / `按默认` / 不答 | 命中缺省值表 | Q1 缺省：不筛选（全员进入判定），摘要注明"本次未设置筛选规则" |

## 四、Q1 解析反例（易错，禁止这样解析）

| 输入 | 错误解析 | 正确解析 |
|---|---|---|
| `23` | 理解为"第二十三个选项" | 组合：类型2 + 类型3（按位拆分） |
| `2ba` | 把 b、a 都当成类型2 的取值 | 类型2 只取第一个字母为列（b 列）；a 是上一组合中类型3 的列 |
| `选5只保留本科生` | 把"本科生"当字母参数 | 含 5 → 整段为自定义规则原文，不拆分 |
| `3` | 当成"第三列" | 数字 = 类型选择（类型3 按列优先级），列字母需再输入 |
| `bacd` | 当成类型2 保留 4 个取值 | 纯字母无数字 → 默认类型3：b=列，acd=优先级 |
| `2b` 后不追问取值直接执行 | 缺少参数就执行 | 同一轮内追问一次取值，再不答用缺省（全员保留并注明） |
| `把研究生剔掉` 按"保留研究生"执行 | 方向反了 | "剔除 X" = 保留其余；"保留 X" = 只留 X，方向必须按句子语义 |
| 用户输入中文数字"二三" | 当成类型选择 | 无阿拉伯数字 → 按自然语言自定义（类型5）处理并回存 |
| 拿本文件示例列名（意向教练性别等）去真实表里找列 | 按样本样式反向推断表结构 | 禁止；一切以实际表头识别 + 可筛列提取结果为准（不预设表格模板） |

## 五、Q2 状态判定 · 解析正例

| 用户输入 | 解析过程 | 解析结果 |
|---|---|---|
| `A 30 10` | 模式A，N=30、M=10，无排序编号 | 名额制：录取 30、候补 10，按报名时间（缺省排序依据 1） |
| `A30 10 2` | 模式A，前两个数字 30/10，末尾 2 | 名额制：录取 30、候补 10，按列优先级（复用 Q1 类型3 所选列与字母链，不重问） |
| `A 30` | 模式A，只给一个数字 | 录取 30、候补 0（M=0），按报名时间 |
| `B` | 模式B | 全员录取，无候补；3.2 候补组标题写"（无，全员录取模式）" |
| `C 3` | 模式C，分组数=3 | 按排序依据顺序连续均分 3 组（组差 ≤1），输出"3.1 通知第1组…3.3 通知第3组" |
| `D 按意向教练性别分男女教练两组，分别通知` | 模式D | 口述全文为规则，原样回存（含排序/分组语义时跳过排序依据行） |
| `录取30个，候补10个` | 模式A 自然语言 | 名额制：录取 30、候补 10，按报名时间（已在 Q1 口述过的判定部分直接采用） |
| `A 30 10 1+2` | 末尾含组合 | 排序依据组合：时间 + 按列优先级，tie-breaker 学号升序在最后 |
| `随便` | 命中缺省值表 | 模式A：录取 30、候补 10【此为例】，按报名时间 |

## 六、边界情形对照（供执行时快速核对）

| 情形 | 处理 |
|---|---|
| 表头带序号前缀（`1、姓名`） | 匹配前先剥离 `数字 + 、/. ．` 前缀，再走别名表 |
| 合并单元格（Excel） | 读取时先把每个合并区域左上角值填充到区域内所有单元格；数据区合并填充后正常参与清洗；摘要注明"合并单元格 N 处，已填充" |
| 多行表头（第 1 行是合并大标题，第 2 行才是列名） | 表头行探测：取前 5 行中命中别名关键词最多的行作为表头行；上方标题行跳过并注明，不进入数据 |
| CSV/粘贴文本 | 无合并单元格概念，跳过该步 |
| 平台元数据列（序号/所用时间/来源/来源详情/来自IP） | 跳过，摘要注明；不参与清洗与筛选、不进可筛列 |
| 多选拆列识别先于别名匹配 | 同一题拆分的多列先判定为多选拆列，不再做别名匹配（避免选项名含"书院"等关键词被误识别为具名列），不进可筛列 |
| 多列命中同一别名（如"性别"与"意向教练的性别"） | 消歧：全等优先 → 取列名最短且不含"意向/预期/期望"等修饰词者归入；其余命中列保留为普通列（可进可筛列），摘要注明 |
| 表格形态与示例不同（其他平台/手工表） | 不预设模板：按实际表头识别 + 可筛列提取结果处理 |
| 多 sheet | Q0 追加独立编号行（1.正式报名 2.测试数据 3.合并全部）；缺省 = 第一个含数据（≥1 行）的 sheet；选 2/3 重清洗后重显摘要，不再确认 Q0，直接进 Q1 |
| 选项值提取时机 | 必须在 Q0 最终确认之后计算（多 sheet 选择会改变数据） |
| 可筛列定义 | 所有列（含未识别列，如"意向教练的性别""一等奖意向奖励"）中取值种类 ≥2 且 ≤10；排除关键列（姓名/学号/邮箱/联系方式）、平台元数据列、报名时间列、多选拆列 |
| 编码列（0/1、1/2/3） | 标注"（编码）"；请用户口述取值含义，记入规则参数原文，供"判定理由"引用 |
| 自然语言中的取值匹配不到列/取值 | 归入自定义规则原文并回显确认，不猜测 |
| 拖入筛选标准.md | 按内容结构识别（含"筛选规则/状态判定规则"字样）；Q0 照常问；以文件内容为 Q1/Q2 答案，回显要点确认后按该内容重置写入（Q3 自动重置，无沿用/修改/更换确认） |
| 多文件列结构不一致 | 规则依赖字段缺失的记录不剔除，进异常清单（"身份缺失，无法判定"）+ 待确认事项；判定按最保守语义（不因缺失落选） |
| 类型1 与 Q2 排序依据冲突 | 以 Q2 明确选择为准，注明"类型1 先到先得与排序依据冲突，按排序依据执行" |
| Q2 选排序依据 2 但 Q1 未设类型3 | 该选项标注"（Q1 未设置该优先级，不可选）"；已选且实际选错 → 降级为时间排序并注明，待确认事项记录 |
| 参数缺失（选 2 未选列、选列后未选取值） | 同一轮内追问一次 → 再不答用缺省（类型2=全员保留并注明；类型3=仅按时间排序并注明） |
| 表无邮箱列但有微信列 | 全员按学号推导邮箱进收件人串；微信列仅作联系信息保留在名单与内部记录，不进收件人串 |
| 同日多次运行 | 按 (活动名, 日期) 配对追加 -2/-3；不同活动同日互不影响；同轮修正覆盖同名，不产生新序号 |
| 文件名非法字符 | `\ / : * ? " < > |` 替换为 `-` |
| 数据量 > 500 行 | 简报与文档加注"数据量大，请抽查核对" |
