# 邮件筛选技能 v2.0（mail-screening-v2）

报名表清洗、筛选与分组，输出分组名单与英文分号收件人串；确认后直接生成各组邮件正文与群通知（对话 Markdown 交付，含主题行）。

> v2.0 全新体系：**自动清洗 → 选择题式一轮 grilling（选项来自表格数据）→ 统一执行 → 统一输出 → 存档为工作日志**。
> 旧版"渐进式交互（边处理边汇报）"已废弃。

## 目录结构

| 文件 | 作用 |
|---|---|
| `SKILL.md` | 技能指令（六阶段流程 + 内置规则库 + 缺省值表 + 强制要求 + 文首「唯一配置区」+ §13 邮件与群通知写作模块），固定不变 |
| `references/输入解析与边界示例.md` | Q1/Q2 输入解析正反例表（技能内部参考） |
| `标准模板.md` | 可选输入模板：想以文件方式直接给标准时使用（拖入对话即视为 Q1/Q2 已答）；技能不会自动回存 |

## 安装

1. 将本文件夹（`筛选+邮件 V3/`）复制到你的 Claude Code 技能目录：
   - 个人使用：`~/.claude/skills/筛选+邮件 V3/`
   - 仅当前项目：项目根目录下 `.claude/skills/筛选+邮件 V3/`
2. **如已安装旧版「邮件筛选」（mail-screening），建议删除旧版文件夹**（`~/.claude/skills/邮件筛选/` 等），避免两个技能同时匹配触发造成行为混乱。本技能 name 为 `mail-screening-v2`，可与旧版共存，但同一场景只应有一个技能响应。

## 快速开始

自然语言直接说即可，例如：

- "筛选这份报名表，按标准分组"
- "帮我群发邮件" / "发送邮件"
- "处理一下这个纳新报名表"
- 上传报名 Excel/CSV 后说"筛选"

技能会自动匹配调用。上传时同时说出需求 → 跳过开场说明，直接开始处理。

## 使用流程（六阶段）

```
① 开场说明（一句话 + 上传要求；已带文件则跳过）
② 接收与自动清洗（多文件合并 → 清洗 → 清洗摘要，仅展示摘要）
③ grilling 一轮 5 问（Q0 清洗确认 / Q1 筛选选择题 / Q2 判定选择题 / Q3 活动名 / Q4 邮件要素；只存不产）
④ 统一执行（去重 → 邮箱补齐 → 筛选 → 判定 → 分组，中间态不外显）
⑤ 统一输出（对话简报 + 筛选结果-{活动名}-{日期}.txt，存档为工作日志）
⑥ 确认与交付（人工审核 → 逐组生成邮件正文 + 内部区块，对话 Markdown 交付）
```

交互特征：**只问一轮、只存不产、一次输出**。你只需选规则、看摘要、审高危项。

筛选规则两种说法都行（等价）：
- 格式输入：`2b`（类型2 选 b 列）、`3a b,a`（类型3 优先级 b→a）
- 自然语言：`保留女生`、`把研究生剔掉`、`先按某列筛保留女，再按性别优先`——先识别意图再落参数，任何说法都会回显确认。

## 输入要求

- 表格格式：`.xlsx` 优先；解析失败时请另存为 CSV 再上传；也可直接粘贴 CSV 样式文本。
- 可分批次上传多个文件，会自动合并（表头对齐、列差异注明）。
- 表头列名不固定，技能用别名表模糊匹配（姓名/学号/邮箱/报名时间/身份类型/年级/学院/书院/专业/联系方式/性别）。
- **兼容腾讯问卷等平台导出格式**：序号前缀表头（`1、姓名`）、`提交答卷时间`（自动识别为报名时间）、`微信` 列（识别为联系方式，进名单不进收件人串）、平台元数据列（序号/所用时间/来源/来源详情/来自IP，自动跳过）、多选拆列（自动注明）。
- **自动识别合并单元格**：Excel 中的合并区域自动填充（左上角值复制到区域内所有单元格），多行表头（第 1 行是合并大标题、第 2 行才是列名）自动探测并跳过标题行，摘要中注明。
- 表无邮箱列时，收件人串按学号推导邮箱（`{学号}@{域名}`，域名缺省 = 文首「唯一配置区」的默认邮箱域名）；组织域名不同时在对话中口述说明即可（如"域名是 xx.edu.cn"），不说明则用默认值。
- 筛选维度不限于身份/书院/年级：表中任意列（性别、{活动专属列}等）均可作为筛选或优先级依据（Q1 选择题动态列出）。

## 与旧版（v1）的差异

| 旧版 | 新版 |
|---|---|
| 渐进式交互（简报→确认→修改） | 统一输出 + 一次确认（P2 只存储不产出） |
| 找不到标准时自由询问 | 固定问题集 Q0–Q3（选择题式，选项来自表格） |
| 筛选规则自然语言自由填写 | 内置类型库选择题 + 参数，支持自定义 |
| 标准文件自动回存（筛选标准.md） | 不生成文件：标准仅会话内按本次表格与回答重建（绝不沿用），规则原文写入结果文档 |
| 单文件输入 | 多文件合并 |
| 结果固定名覆盖 | 活动名+日期命名，存档为工作日志（不覆盖） |
| 每次完整开场说明 | 一句话 + 已带文件跳过 |
| 示例值无标注 | 全部标注【此为例】 |

## 邮件写作能力（已并入本技能，一体交付）

本技能管"**给谁发**"（清洗、筛选、分组、收件人串），并直接管"**发什么**"（各组邮件正文与群通知）——邮件写作功能（仅邮件 + 群通知范围）为 §13 内置规则（含核心语言调教、信息层纪律、能力状态检查与内部交付区块），本组件为完全独立自洽的技能，不依赖任何外部技能。

1. grilling 新增 Q4 收集邮件要素（活动时间/地点/主题/报名链接/报名截止/联系人/抄送），随结果文档「6. 邮件要素」存档，形成完整文件。
2. 你核对分组无误后，本技能直接生成各组邮件正文（对话 Markdown，含主题行），并附内部区块（状态检查/发布状态/待确认/本次变更）。
3. **不需要邮件正文时**：Q4 填写"无"或不填即可，技能自动跳过邮件生成，仅交付筛选结果。
4. 组织身份默认以文首「唯一配置区」为准（默认 TIDE Club；**换组织只需修改该区**）；用户明确指定其他组织或要求去除品牌时，以用户为准。
5. 公众号/海报/朋友圈/双语/多渠道内容包不在本技能范围；如需要此类文案，请另行使用其他独立文案技能（本组件不含）。

## 输出文件说明

- `筛选结果-{活动名}-{YYYY-MM-DD}.txt`：每次运行的结果（markdown 格式），**不覆盖、自动保留**，构成工作日志——历史活动全程可查；同日多次运行追加 `-2`、`-3`；旧文件由你手动清理。文档含「6. 邮件要素」区（Q4 收集的时间/地点/主题/链接/截止/联系人/抄送）。
- 本技能不生成筛选标准文件：筛选标准每次运行按本次表格与回答在会话内重建（绝不沿用上次），规则原文随结果文档落盘。
- 邮件正文以对话 Markdown 交付（可复制），不写入结果文档；仅用户明确要求时才生成 Word/HTML/PDF/TXT 文件。
- **宿主环境不支持写文件时**（如部分第三方集成）：结果文档自动降级为对话 Markdown 完整交付（§7.4），简报注明原因并给出建议文件名，不伪造存档。

## 强制要求速览

1. 收件人串用**英文分号 `;`**（不是中文分号 `；`），不加空格，结尾无多余分号——Outlook 直接识别。
2. 宁报告不静默丢弃（异常清单）。
3. 统计数字与名单逐条对应，可复现。
4. 姓名/学号/邮箱字段原样保留，不改写。
5. 只输出规格规定的文档本身；环境无法输出文件时降级为对话 Markdown 完整交付（§7.4）。
6. 邮件正文事实必须来自 Q4/用户提供，缺失进「待确认」，绝不编造。
7. 邮件正文以对话 Markdown 交付（含主题行），用户明确要文件才生成；文件动作在「状态检查」如实标注。

回答"随便 / 按默认"也有确定行为（缺省值表兜底），绝不卡住追问。
